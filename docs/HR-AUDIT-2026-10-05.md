# HR application audit and fixes — 5 October 2026

Reviewed the API, shared UI, payroll, report exports, permissions and existing
test setup from main commit `dfbcdb60c213a5ad78feaa87b0ab1d7c0fdbdd37`.
This is a verified set of fixes, not certification that every module or the
original product specification is complete.

## Fixed

- HR editors without payroll access no longer erase hidden employee bank fields
  when saving personal details. Attempts to edit those bank fields remain denied.
- Employee accounts cannot enumerate company salary payout records. Provider
  status synchronization now requires payroll approval permission.
- Payroll preparation marks only adjustments actually included in a payroll item
  as applied. Adjustments for excluded employees remain pending through recalculation.
- Payroll calculations reject non-finite percentages, invalid caps and unsafe
  integer totals instead of producing invalid money values.
- Employee CSV, Excel and PDF reports fetch all matching pages, with deterministic
  ordering. Directory export links include the current search and status filters.
- Excel sheet names are cleaned and shortened before XML escaping, avoiding
  broken XML when a long title ends with an ampersand.
- Dialogs have accessible names; clicking their internal padding does not dismiss
  the form. Time and duration controls use their actual field labels.
- Forms guard against duplicate submissions and serialize hours as numbers.
- Select fields request up to 500 options instead of the default first 25.
- Status choices remain available after filtering; deleted last-page records no
  longer leave the directory on an empty page. Empty searches have Clear filters.
- Employee deletion copy accurately describes retained raw punches and historical
  payroll, and the operational records that are removed.
- Notifications reject protocol-relative and backslash-based external links.
- SSR smoke checks no longer consume the session response body twice.

## Verification

- Baseline: typecheck, 62 unit tests and 14 integration tests passed.
- Updated: 68 unit tests and 17 integration tests passed. Integration coverage
  includes bank-field preservation, payout authorization, a 501-employee filtered
  export, and excluded payroll adjustments.
- Backend compilation passed.
- Full frontend build and browser startup were attempted, but this execution
  environment throws `ENOENT: uv_resident_set_memory` from Node's memory-usage API.
  A Chromium installation attempt could not complete because network approval
  was cancelled. No visual/browser pass is claimed.

## Remaining before a complete release

- Run the full frontend build and desktop/mobile browser flows in CI or a normal
  development environment; update the older browser suite's selectors and fixtures
  for the current required employee fields and delete workflow.
- Visually review dashboard, tables, long forms, mobile navigation and error states.
  This patch improves interaction/accessibility; it does not claim a full redesign.
- Verify real biometric devices, email, object storage and payment-provider flows
  using an explicitly configured test environment. No live payouts were performed.
- Review concurrency across payroll preparation, reopening, deletion and payout
  initiation; not all paths currently share one locking convention.
- Upgrade large-directory selectors to searchable server-side selection, and audit
  pagination/filter completeness in reports other than employee exports.
- Review deployment migrations, existing embedded-database upgrades, backups and
  restore behavior against a copy of production data before deployment.
- Reconcile `docs/IMPLEMENTATION_STATUS.md` and the original specification against
  current customer requirements. Statutory payroll, advanced approvals, vendor
  connectors and external integrations need their own acceptance criteria.

The fixes are proposed on a separate branch. Production configuration, live data,
main branch and deployment have not been changed by this audit.
