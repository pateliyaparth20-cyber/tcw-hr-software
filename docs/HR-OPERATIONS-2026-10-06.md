# HR operations expansion — 6 October 2026

This release adds working, permission-checked workflows to the existing HR software.

- Payroll → Salary structures: immutable effective-month salary revisions, Basic/HRA/allowances breakdown and an explicit overtime hourly rate. Payroll uses the structure effective for its month, retains an opening baseline, rejects changes affecting prepared payroll and rejects stale profile edits. Profile salary changes before the first structure also record their current-month history. Manual final salary remains separate and retains deductions.
- Payroll → Loan and advance recovery: up to 60 scheduled monthly installments, correct final partial installment, outstanding/recovered totals and cancellation of unapplied future installments. This records recovery of an existing loan; it does not disburse funds. Recalculation, finalization and reopening preserve the installment bookkeeping.
- Company profile → Approval levels: optional reporting-manager then HR/Finance approval for new leave, expense and travel requests. Existing single-review requests retain their policy. Two-stage requests snapshot their manager and keep pending status until final approval. Reviewers cannot approve themselves or complete both stages; rejection requires a reason. Requests without a manager route to the final reviewer.
- People → Import employees: native CSV/XLSX templates, bounded spreadsheet parsing, create/update modes, reference validation, duplicate and plan-limit checks, preview with row errors and atomic commit tied to the preview digest. Updates retain bank details, photos and personal data. Structured salary revisions must use the salary workflow. Headings and enumerated values accept capital or small letters, spaces, underscores and hyphens. Joining dates accept native Excel dates (1900/1904 systems), YYYY-MM-DD or DD/MM/YYYY; money is entered in company currency units with optional valid thousands separators. Employee-code matching and duplicate detection ignore letter case while updates retain the stored code. The detailed preview scrolls horizontally and vertically on desktop and mobile.
- People → Checklists: idempotent joining/exit templates, custom tasks/deadlines, completion actor/time and stale-edit protection. Appointment, experience and relieving PDFs use recorded employee details. Experience/relieving letters require completed offboarding. Signature and contract terms remain company-controlled.
- Training → Participants: enrollment, capacity enforcement, completion/score tracking and downloadable completion certificates. Courses with enrollments cannot be deleted. Cancellation retains history.
- Assets → History: assignment, return, status and deletion events retain employee name/tag snapshots. History starts with changes recorded in this release; it does not reconstruct old events.
- Documents: optional expiry dates with expired/expiring-document alerts. People shows checklist, device-heartbeat and unresolved-payout counts when the account can view those resources.
- Reports: shared queries for previews and CSV/XLSX/PDF downloads, date/department/branch filters and a per-employee payroll report. Downloads contain the complete matching result; previews remain bounded. Department/branch membership reflects current directory assignments; payroll names/amounts retain their run snapshots. Recruitment has departments but no branch mapping.
- Payroll → Payment reconciliation: all salary-transfer references, status, UTR and verification errors across months. Provider status checks do not initiate payments. Transfers without a verified provider ID require provider-dashboard reconciliation. Existing duplicate-transfer protections remain.
- My security: encrypted authenticator setup, confirmation before enabling, RFC 6238 TOTP with bounded drift and replay protection, ten hashed single-use recovery codes and password/code-protected disabling. Enabling/disabling revokes other sessions. CONFIG_ENCRYPTION_KEY must be configured; unavailable encryption is shown explicitly. Password resets retain enabled second-factor protection.

Two additive Prisma migrations create the new tables. Existing payroll, employees, permissions and provider settings are not rewritten on deployment. Production records are not used for mutating tests.

Validation includes type checking, unit tests (including RFC vectors and spreadsheet boundaries), isolated HTTP integration flows, PostgreSQL concurrency tests, frontend builds and Chromium workflows for imports/checklists, salary revisions, policy persistence, training completion and authenticator/recovery sign-in. CI also dumps the isolated PostgreSQL service, restores it into a separate database and compares the contents of every public table.

## External acceptance still required

The code and test-database restore drill are not evidence of production backup retention or disaster recovery. Configure/verify those on Railway separately. SMTP/S3/payment-provider credentials and live delivery must be verified in the deployment environment. Additional biometric vendors require exact hardware/protocol validation. Statutory deductions remain configurable and require jurisdiction-specific policy review; this release does not certify compliance. Provider webhooks, dispatch recovery and verified retry of transfers without a provider ID remain follow-up work.
