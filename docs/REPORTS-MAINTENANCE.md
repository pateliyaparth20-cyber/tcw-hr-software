# Reports maintenance

Reports default to maintenance when `REPORTS_MAINTENANCE` is unset. This release intentionally blocks all accounts, including new accounts, until a preview identity is explicitly approved or maintenance is disabled. `REPORTS_MAINTENANCE=true` also activates maintenance. All authenticated accounts are blocked from report previews and CSV, Excel, PDF, attendance summary and bank payout report downloads unless explicitly excepted. Existing resource permissions and tenant scope still apply to excepted accounts. The UI checks `/api/reports/access` before mounting report queries; blocked users see a blurred static layout containing no company data and an Under Maintenance message. Account exception configuration is never returned to browsers.

Prefer `REPORTS_PREVIEW_USER_IDS` containing the one approved existing user UUID. If only login details are available, configure all three values: `REPORTS_PREVIEW_COMPANY_CODE`, `REPORTS_PREVIEW_LOGIN` (exact login ID or login email), and `REPORTS_PREVIEW_CREATED_BEFORE` (ISO timestamp captured before activation). Company code isolates matching logins in different companies. The timestamp prevents accounts created after configuration from inheriting this exception. An empty or incomplete exception denies everyone while maintenance is enabled; role changes alone never grant access.

Before adding an exception, verify the approved account identity. Setting `REPORTS_MAINTENANCE=false` restores normal permission-based reports; removing the value keeps maintenance active. No database migration is needed.

The report center has role-filtered report search, categories, date presets, department and branch filters, a full-column preview (first 25 rows), and downloads with busy/error feedback. Recruitment has no branch assignment: clear Branch to preview or export it. Directory and asset reports are current snapshots rather than date-range reports. No sample or cached company data is rendered in the maintenance backdrop. All three portals follow the manual-update `release/production` branch; merge this change to main as a candidate and wait for an authorized Update software request rather than deploying automatically.
